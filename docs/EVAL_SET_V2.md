# 真实年报评测集 v2

## 数据规模

| Split | 数量 | 是否冻结 | 用途 |
|---|---:|---|---|
| Dev | 60 | 否 | 检索、重排、路由和提示词调优 |
| Test | 30 | 是 | 项目最终验收，只在里程碑结束时运行 |
| No-answer | 15 | 是 | 无证据拒答评测 |
| 合计 | 105 | — | 90道有答案题、15道无答案题 |

语料保持为3家公司、2个年度、6份年报，共1,609页、2,775个Chunk。

## 问题分布

| 类型 | 数量 |
|---|---:|
| 财务单事实 | 42 |
| 研发 | 18 |
| 员工 | 12 |
| 分红 | 6 |
| 跨年度 | 12 |
| 无答案 | 15 |

开发集和测试集均覆盖6份报告。测试集保留了开发阶段未直接使用的基本每股收益、
净资产收益率、资产总额和研发人员等事实模板，并包含6道跨年题。由于文档集合较小，
两个 Split 仍共享报告和部分证据页，因此它衡量的是“问题泛化”，不是“新文档泛化”。

## 无答案设计

- 9道超出时间范围的问题：3家公司各自的2026年收入、研发投入和员工数；
- 6道超出公司范围的问题：贵州茅台、腾讯、阿里巴巴、特斯拉、苹果和华为；
- 所有题的 `relevant_chunk_ids` 为空，`expected_action` 为 `refuse`；
- 无答案题必须单独计算拒答准确率，不得混入普通 Recall/MRR。

## 证据与质量控制

每道有答案题包含：

- 唯一 `query_id`；
- `answer` 和原报告单位；
- 一个或多个 `relevant_chunk_ids`；
- `source_pages`；
- 公司、年份、事实类型和 Split 元数据。

构建时对财务、研发、员工和分红证据页进行了逐项核对。验证脚本进一步检查：

1. 相关 Chunk 必须真实存在；
2. 答案中的每个数字必须出现在证据文本中；
3. 页码必须与相关 Chunk 一致；
4. 105道问题的 ID 和规范化文本不得重复；
5. 冻结文件的 SHA-256 必须与 Manifest 一致。

运行方式：

```powershell
python scripts/build_eval_v2.py
python scripts/validate_eval_v2.py
```
