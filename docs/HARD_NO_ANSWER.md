# 范围内困难无答案集

## 为什么需要补充

原15题 No-answer 只覆盖公司或年份越界。真实系统还会遇到更危险的情况：公司、年份和基础字段
都有效，但用户询问年报没有披露的细分口径。检索器通常仍会召回“公司总数”，如果不检查问题
限定条件，系统会把总数误答成细分答案。

本项目新增非冻结开发集：

`data/eval/annual_report_hard_no_answer_dev_v1.jsonl`

共18题，三家公司、两个年份各3题：

- 海外研发投入金额：年报披露研发总额，但没有地区拆分；
- 女性技术人员数量：年报分别披露技术人员和部分人员结构，但没有交叉统计；
- 业务分部净利润：年报可能披露分部收入，但没有该分部对应的归母净利润。

每题均处于有效公司和年份范围，且继续调用受控回答器已支持的基础财务字段。该集合
`frozen=false`，只能用于开发和阈值分析。

## 校验

```powershell
python scripts/build_hard_no_answer.py
python scripts/validate_hard_no_answer.py
```

校验会检查：

- 18个唯一问题；
- 公司和年份均在当前语料范围内；
- 每题都能映射到已支持的基础字段；
- 每题都包含可解析的额外证据约束；
- 2,775个Chunk中不存在同时满足所需限定词与字段关系的直接证据；
- 不读取冻结 Test。

## GPU实验

```powershell
python scripts/run_hard_no_answer_evaluation.py
```

| 仅分数阈值0.995 | 94.44% | 66.67% | 50.00% |

| 查询约束—证据蕴含检查 | 100.00% | 100.00% | 100.00% |

结论：Qwen3-Reranker 对“相关但不能回答”的页面同样会给高分，单一阈值无法同时保持回答率和
拒答率。当前采用限定词与字段关系检查，不设置正的全局 Reranker 阈值。

## 实现范围与限制

当前识别三类限定条件：

- 地区：海外、境外、欧洲、北美；
- 技术人员交叉属性：女性、博士、硕士；
- 业务分部：储能/动力电池、智慧教育/医疗、新能源汽车业务。

这仍是受控模式，不是完整的自然语言蕴含模型。后续可以加入：

- 更多产品、地区和会计口径别名；
- 一个独立的小型 NLI/LLM Judge；
- 对困难无答案集做人工双人复核；
- 冻结新的语义无答案 Test，而不是继续在当前开发集上调规则。
