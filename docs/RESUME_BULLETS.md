# 简历与面试表述

## 推荐项目名称

面向上市公司年报的评测驱动 RAG Agent

## 简历版

- 面向 6 份真实中文上市公司年报构建评测驱动 RAG Agent，完成 PDF 解析、2,775 个
  Chunk 结构化索引、BM25 + Dense + Qwen3-Reranker 混合检索、受控答案抽取及页码引用。
- 基于 48 个训练问题挖掘 1,152 条难负例，在 RTX 4060 8GB 上微调 BGE-small；
  12 题留出验证集 Dense Recall@1 从 20.8% 提升至 91.7%，Recall@10 达到 100%。
- 设计公司/年份路由和查询约束—证据蕴含拒答机制，18 题范围内困难无答案集拒答准确率
  达到 100%，而仅使用 Reranker 阈值为 0%。
- 建立配置哈希锁和一次性冻结测试门禁；30 题 Test 上检索全部 Gold 证据 Recall@10
  为 96.7%，并定位端到端 20% 准确率的主因是 4 类测试专属字段未被规则答案器覆盖。
- 在 8GB RTX 4060 上采用 Embedding/Reranker 顺序卸载，最终推理峰值显存约 1.75 GiB；
  提供 FastAPI + Web 演示、68 个自动化测试和可复现实验脚本。

## 30 秒面试版

这个项目的重点不是套一个 RAG 页面，而是把检索、回答、拒答和评测拆开验证。我用真实年报
构建了 BM25、微调 BGE-small 和 Qwen3-Reranker 的混合链路，并通过难负例训练把留出集
Dense Recall@1 从 20.8% 提升到 91.7%。我还设计了范围内无答案测试，证明单靠相关性分数
不能可靠拒答，需要查询约束和证据蕴含检查。最终冻结测试的检索 Recall@10 是 96.7%，但
端到端只有 20%，我通过 Oracle 实验确认瓶颈是规则答案器缺少测试专属字段 Schema，而不是
检索。这体现了我会保留真实失败结果，并用分层评测定位系统瓶颈。

## 不建议写法

- 不要把 12 题微调留出验证集的 100% Recall@10 写成“最终测试集 100%”。
- 不要只写 Dev 端到端 100% 而隐瞒冻结 Test 的 20%。
- 不要声称系统支持任意财务字段；v1 只支持已注册字段。
- 不要把 Qwen3-Reranker 描述成自己训练的模型。
