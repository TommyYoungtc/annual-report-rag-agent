# 简历与面试表述

## 推荐项目名称

面向上市公司年报的评测驱动 RAG Agent

## 简历版

- 面向 14 份真实中文上市公司年报构建评测驱动 RAG Agent，完成 4,076 页 PDF 解析、
  6,831 个 Chunk 结构化索引、BM25 + 微调 BGE-small + Qwen3-Reranker 混合检索、
  受控答案抽取、拒答和页码引用。
- 基于 48 个训练问题挖掘 1,152 条难负例，在 RTX 4060 8GB 上微调 BGE-small；
  12 题留出验证集 Dense Recall@1 从 20.8% 提升至 91.7%，Recall@10 达到 100%。
- 扩展 8 类财务字段 Schema 与查询约束—证据蕴含拒答机制；122 题 Dev 精确答案准确率
  和 30 题困难无答案 Dev 拒答准确率均为 100%。
- 建立配置哈希锁和一次性冻结测试门禁；在锁定配置后选取 2 家零重叠公司构建 32 题
  盲测，端到端准确率 **93.75%（30/32）**、Gold 证据 Recall@10 **100%（32/32）**；
  定位剩余错误为年度指标与分季度指标的章节混淆。
- 在 8GB RTX 4060 上采用 Embedding/Reranker 顺序卸载，最终推理峰值显存约 1.75 GiB；
  提供 FastAPI + Web 演示、76 个自动化测试和可复现实验脚本。

## 30 秒面试版

这个项目的重点不是套一个 RAG 页面，而是把检索、回答、拒答和评测拆开验证。我用 14 份
真实年报构建 BM25、微调 BGE-small 和 Qwen3-Reranker 的混合链路，并在 RTX 4060 8GB
上完成训练和推理。V1 冻结测试只有 20%，Oracle 证明瓶颈是字段 Schema 覆盖；我在新公司
和新测试集上做 V2.1，而不是修改原测试刷分。V2.1 先锁配置、再选两家零重叠公司，唯一一次
32 题盲测端到端准确率 93.75%，检索 Recall@10 为 100%。剩余两题是年度页和季度页混淆，
说明下一步应该改章节判别，而不是继续调召回。

## 不建议写法

- 不要把 122 题 Dev 的 100% 写成“最终测试集 100%”。
- 不要把已用于规则迭代的海康威视、美的集团 100% 写成独立测试结果。
- 对外应写 V2.1 冻结盲测 93.75% 和检索 Recall@10 100%，并保留两道失败说明。
- 不要声称系统支持任意财务字段；V2.1 只支持 8 类已注册字段。
- 不要把 Qwen3-Reranker 描述成自己训练的模型。
