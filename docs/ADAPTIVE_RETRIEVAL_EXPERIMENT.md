# Adaptive Retrieval 实验协议

## 研究问题

本实验检验一个具体问题：固定执行多轮检索是否值得，还是应当根据当前证据的充分性决定是否继续检索。实验不比较不同 Embedding 或 Reranker，也不允许三套系统使用不同答案器。唯一主要变量是检索控制策略。

主要假设是：Adaptive 系统能保持 Static RAG 的开发集答案质量，同时用显著少于 Always Agentic 的检索轮数、Reranker 调用和时间。次要假设是：当首轮证据来自分季度章节而问题询问全年指标时，Evidence Verifier 能识别时间粒度不一致并触发定向检索。

## 三套系统

### A Static RAG

A 固定执行一轮。它使用现有的元数据过滤、微调 BGE-small、BM25、加权 RRF、Qwen3-Reranker 和受控答案器。A 是 V2.1 主链路的可复现基线。

### B Always Agentic

B 对可检索问题最多执行三轮。只要没有得到终止型拒答，B 即使首轮证据充分，也继续使用预先定义的查询扩展检索。B 用于测量“所有问题都增加 Agentic Retrieval”能够获得的质量上限和预算代价。

### C Adaptive Budget Aware

C 首轮与 A 完全相同。每轮结束后，Evidence Verifier 检查公司、年份、字段、引用覆盖和年度季度粒度。证据充分时立即回答；证据不足时继续检索；带额外约束的无答案请求至少确认两轮后才拒答；最多三轮。

## Evidence Verifier

Verifier 不读取标准答案、Gold Chunk 或来源页码，只能看到问题、路由结果、当前检索证据和系统基于这些证据生成的答案。当前检查项为：

- 公司和年份引用是否完整；
- 回答是否具有可追溯的 Chunk 引用；
- 全年问题是否引用了纯分季度指标页面；
- 答案器是否因缺少字段、单位或查询约束而拒答；
- 带地区、员工属性或业务分部约束的问题是否经过第二轮确认；
- 是否已经达到最大检索轮数。

Verifier 输出 `sufficient`、`insufficient` 或 `terminal_refusal`，并记录结构化原因。它不改写当前轮答案；只有检测到年度/季度冲突后，下一轮才会排除已证实时间粒度错误的证据，并修复 PDF 中文断行与“母公司股东/上市公司股东”同义表达，再交给同一个受控答案器。

## Query Rewriter

本候选版本使用固定规则，目的是隔离检索控制策略，避免把 Prompt 或模型变化混入 A/B/C 对比。第二轮添加字段别名、年报章节和“年度、全年、非分季度”等粒度词；第三轮补充合并财务报表、本年数和本期金额等表达。原始公司、年份和字段始终保留。

本轮不调用生成式 Planner，因此 Planner Token 和 API 成本为零。轨迹格式已经预留 Token 和价格字段，后续可以在相同实验协议下替换成固定 LLM Query Rewriter，不能同时修改数据、预算和评分规则。

## 数据划分

开发与消融使用 `annual_report_v2_dev.jsonl` 的 122 道可回答问题，以及 `annual_report_v2_hard_no_answer_dev.jsonl` 的 30 道困难无答案问题。

V2.1 冻结测试中的两个已知错例仅作为开发期回归 canary，用于验证年度季度检查是否触发。它们不进入任何聚合 Dev 指标，也不得被重新表述为冻结测试成绩。

新的 V3 冻结测试必须在本候选配置锁定后选择全新公司，开发公司交集必须为零。测试标签在候选锁之后创建、首次运行之前冻结，最终只允许一次成功运行。

## 统一轨迹和成本

每题每轮记录：检索 Query、候选数量、Reranker 输入段落数、证据 Chunk 和分数、答案状态、Verifier 结论、下一步动作、检索时间、重排时间、分摊的模型加载时间、Planner Token 和估算 API 成本。

质量指标包括精确答案、Gold Evidence Recall@10、引用 Chunk、引用页码和无答案拒答。预算指标包括平均检索轮数、Dense 与 BM25 查询次数、Reranker 调用与段落数、Token、P50/P95 延迟和每个正确答案的成本。

由于当前 Planner 为确定性规则，货币成本为零。当前阶段主要比较每个正确答案消耗的重排段落数和分摊推理时间；未来接入付费 LLM 后再计算真实 `Total API Cost / Correct Tasks`。

## 结果解释规则

- 122 题 Dev 已参与规则开发，不能当作盲测；
- 两个 V2.1 错例是已知 canary，不得计入新测试；
- 如果 B 与 C 没有提高 Dev 准确率，这不等于实验失败；Dev 的 Static 基线已经是 100%，此时主要观察多轮检索是否浪费预算；
- 只有新的公司级冻结测试才能支持泛化结论；
- 不允许在新测试运行后修改 Verifier、Query Rewriter、最大轮数或评分脚本再重跑。
