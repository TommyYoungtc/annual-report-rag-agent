# Token-Aware / Cost-Aware RAG V4 开发回放报告

## 1. 结论

在当前旧 Dev 的 152 道任务（122 道可回答、30 道困难无答案）上，使用 Qwen3-Reranker-0.6B 的原生 tokenizer 对生成请求进行 chat-template 后精确计数。最终 Dev 候选采用“自适应 small/large 路由 + 压缩 Prompt + Top-10 证据窗口/4,096 Token 上下文预算”，规则答案器的答案准确率、困难无答案拒答率、全部 Gold Evidence Recall、引用 Chunk 精度和引用页码集合准确率均保持 100%。

与完整 Prompt、全部 large、Top-10 完整 Chunk 的 Baseline 相比：

- 总 Token 代理量从 946,936 降至 542,858，下降 42.67%；
- 平均每个正确答案 Token 从 6,229.84 降至 3,571.43；
- 证据上下文 Token 保留率为 56.22%；
- 152 道题中 110 道被路由到 small、42 道路由到 large；
- 在 small 相对成本系数 0.25、large 为 1.0 的供应商无关设定下，归一化成本下降 72.26%。

以上不是 API 账单，也不是生成式 LLM 质量结论。回放没有调用 Provider，输出 Token 是确定性答案序列化后的代理量，美元费用为空。只有接入并锁定具体 small/large 模型后，才能依据 Provider `usage` 验证 Prompt 压缩和模型路由是否真的不降低 LLM 质量。

## 2. 消融结果

| 配置 | 答案准确率 | 无答案拒答 | Gold Recall | 引用 Chunk 精度 | 页码准确率 | 总 Token | Token 降幅 | 归一化成本降幅 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Baseline | 100% | 100% | 100% | 100% | 100% | 946,936 | 0% | 0% |
| 仅模型路由 | 100% | 100% | 100% | 100% | 100% | 946,936 | 0% | 54.30% |
| 仅 Prompt 压缩 | 100% | 100% | 100% | 100% | 100% | 933,408 | 1.43% | 1.32% |
| 仅上下文裁剪 | 100% | 100% | 100% | 100% | 100% | 556,386 | 41.24% | 38.19% |
| 组合方案 | 100% | 100% | 100% | 100% | 100% | 542,858 | 42.67% | 72.26% |

Prompt 压缩单独收益较小，因为完整 Chunk 占据了绝大部分输入 Token；上下文裁剪是主要 Token 节省来源。模型路由不改变 Token 数，只改变不同模型承载 Token 的比例，因此只反映在归一化成本中。

## 3. Dev 失败与修正

第一版裁剪策略使用 Top-6、2,048 Token。完整 Dev 上答案准确率和 Gold Recall 均为 93.44%，8 道题的 Gold Chunk 位于第 7–10 名，因此该候选被判定不合格。

第二版恢复 Top-10 并将预算提高到 4,096 Token 后，仅剩一道“技术人员”题错误。原因是裁剪丢失“员工数量、专业构成及教育程度”章节锚点，使答案器把较早页面中的“核心技术人员、持股 5%”误识别为人数。最终版本在证据窗口中保留结构锚点、原文单位和命中字段附近原文，重新运行后所有质量门槛通过。

这些修改只使用旧 Dev，属于允许的开发与消融过程。失败版本被保留在实验记录中，未接触 V3 冻结测试。

## 4. 已实现工程能力

- 统一 TokenUsage/TokenLedger，区分 `provider_usage`、`tokenizer_count` 和 `estimate`；
- 分阶段记录 input、output、cached input、静态 Prompt、问题、裁剪前后证据和截断前后 Token；
- 支持显式模型价格表；未配置价格时费用保持 `null`，不伪造美元成本；
- OpenAI-compatible 生成适配器保存 Provider 原始 `usage`；
- 完整与压缩 Prompt 均固化 SHA-256；
- 自适应模型路由记录 small/large 选择、复杂度分数和原因；
- 上下文裁剪保留 Chunk ID、公司、年份、页码、章节、单位、结构锚点及数值证据；
- Dev 回放输出包含配置、语料、数据集和来源轨迹 SHA-256；
- 质量门禁要求五项指标相对 Baseline 观察值零下降。

## 5. 下一阶段

1. 选择并固定一个 small 与一个 large 生成模型，以及各自 Provider 价格表；
2. 使用 temperature=0 在旧 Dev 上做真实生成消融，读取 API 返回的 `usage`；
3. 逐题比较答案、拒答与引用，不把 tokenizer 回放当作 LLM 质量证明；
4. 通过后锁定代码、模型、Prompt、路由阈值、上下文预算和价格表；
5. 新建独立 Holdout，最终每个候选只运行一次并立即封存。
